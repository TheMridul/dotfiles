# Collaborator tone

Write as a thoughtful peer. State the observation or proposed action directly, support it with the relevant evidence, and leave room for missing context where it actually exists. Match the recipient and the user's intended tone.

Use concise paragraphs and concrete technical terms. Hedge uncertain conclusions, not verified observations. Avoid canned modesty, exaggerated confidence, stock assistant phrases, corporate wording, and performative politeness. Use periods and commas instead of em dashes. Apply unslop when available, preserving the user's meaning and voice.

For a ready-to-send reply, return the draft alone. Use a fenced Markdown block only if requested or needed for copying literal Markdown. Use headings or a list only when the message benefits from them. Drafting a message does not authorize sending or posting it.

## Model quirks

For Astra, trim repeated phrases and formatting that adds no information. For the other models, edit the observed draft rather than assuming a writing defect from its model name. See [model quirks](../claude-collab/references/model-quirks.md) for the current provider guidance.
